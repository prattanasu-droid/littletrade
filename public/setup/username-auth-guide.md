# เปิดบัญชีออนไลน์แบบ Username + รหัสผ่าน

รุ่นนี้เพิ่มตารางบัญชีใน Supabase แล้ว หน้าแรกเลือก **ออนไลน์ Supabase** เป็นค่าเริ่มต้น

## ทำครั้งเดียวโดยเจ้าของโปรเจกต์

1. เปิด Supabase โปรเจกต์ `iojxyqpysdqjrpdknkmx` → SQL Editor → New query แล้วคัดลอกไฟล์ `/setup/username-auth.sql` ทั้งหมดมารัน (ถ้ายังไม่มีตารางเซฟ ใช้ `/setup/schema.sql` แทน)
2. ไป Authentication → Sign In / Providers → Email แล้ว **ปิด Confirm email** โดยเปิด Email provider และอนุญาตสมัครผู้ใช้ใหม่ไว้
3. หากใช้ Vercel ให้อัปเดตไฟล์จาก ZIP รุ่นล่าสุดลง GitHub และรอ deploy สำเร็จ ต้องใช้หน้าเว็บรุ่นใหม่ด้วย เพราะหน้าเดิมเรียก registerLocal เท่านั้น
4. เปิดเกม เลือก **ออนไลน์ Supabase** → ลงทะเบียนด้วย username และรหัสผ่าน
5. ตรวจ Table Editor → `player_profiles` จะมี `id`, `username`, `created_at` และใน Authentication → Users จะมีบัญชีเดียวกัน

สคริปต์เพิ่มตาราง/ฟังก์ชันและ Trigger โดยไม่ลบเซฟเดิม รหัสผ่านจัดการโดย Supabase Auth ไม่อยู่ในตารางโปรไฟล์

## บัญชีเดิมและความก้าวหน้า

บัญชีที่สมัครในเครื่องก่อนหน้านี้ไม่ถูกส่งเข้า Supabase อัตโนมัติ เข้าเกมด้วยโหมด **บัญชีในเครื่อง** เพื่อเปิดตัวละครเก่าและดาวน์โหลดเซฟ จากนั้นออกจากบัญชี ลงทะเบียนออนไลน์ใหม่ แล้วนำเข้าเซฟในเมนูจัดการเซฟ

การสมัครสร้างบัญชีและโปรไฟล์ทันที ส่วน `trade_game_saves` จะมีข้อมูลหลังสร้างตัวละครและกดบันทึกออนไลน์จากเมนูรูปเมฆ ระบบยังมีเซฟในเครื่องเสมอ

## ทำไมเห็นอีเมลยาว ๆ ใน Authentication → Users?

เป็น alias ภายในรูปแบบ HASH@players.littletrade.invalid ที่สร้างจาก username เพื่อใช้ Supabase Auth โดยไม่เก็บอีเมลนักเรียน ชื่ออ่านได้อยู่ใน `player_profiles.username` และ `user_metadata.username` ไม่ใช่อีเมลที่รับข้อความได้ จึงต้องปิด Confirm email และไม่มีการกู้รหัสผ่านด้วยอีเมลในรูปแบบนี้

## ผลตรวจ

ทดสอบฟอร์มและบริการ Auth ด้วยการจำลอง SDK, รหัสผ่านผิด, SQL ยังไม่ติดตั้ง, Confirm email ยังเปิด, ลงทะเบียน/ล็อกอิน/ออกจากระบบ และกลับมาเปิดเซฟ ทดสอบ SQL บน PostgreSQL 16 จริงในฐานข้อมูลชั่วคราว: Trigger สร้างโปรไฟล์, alias ภาษาไทย, RLS เฉพาะเจ้าของ, anon อ่านไม่ได้, คนอื่นแก้เซฟไม่ได้ และรัน schema ซ้ำได้

การตรวจโปรเจกต์จริงก่อนเผยแพร่รุ่นนี้พบ `mailer_autoconfirm=false` และยังไม่มี `player_profiles` จึงยังไม่สร้างบัญชีทดสอบจริงในโปรเจกต์ ต้องให้เจ้าของทำขั้นตอน 1–2 ก่อน คีย์สาธารณะที่ใช้หน้าเว็บไม่มีสิทธิ์รัน SQL หรือแก้การตั้งค่า Auth
